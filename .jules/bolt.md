## 2024-05-24 - Bash Script Performance: Batching jq calls
**Learning:** In bash test suites handling large JSON outputs or files, invoking `jq` repeatedly for individual field extraction incurs significant process spawning and JSON parsing overhead, leading to slower test execution. This is a noticeable bottleneck in environments that run tests frequently. Constructing an array inside a single `jq` filter and exporting via `@tsv`, combined with `IFS=$'\t' read -r var1 var2 < <(...)`, dramatically reduces execution time (from ~100ms to ~30ms locally). Furthermore, when executing tests locally using a mock API, `jq` throws errors when iterating over `null` elements (which happen when error JSON without an expected array structure is returned). Using the `?` operator alongside `select()` prevents these errors during execution.

**Action:** Whenever parsing multiple variables from the same JSON object or file in bash, combine them into a single `jq` command that outputs TSV. Use the `?` operator for optional chaining in array iterations (`.sessions[]?`) and when checking object properties. Make sure to handle `null` input strings correctly in evaluations.
