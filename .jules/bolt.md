## 2024-09-05 - Batching jq queries for bash performance
**Learning:** Found a major performance bottleneck where multiple `jq` calls were made sequentially on the exact same large JSON payload in bash scripts. This spawns a new process and parses the entire payload for every single query, incurring massive overhead. The mock tests demonstrated this took around 70ms, whereas batching took 8ms (an 88% reduction in overhead). However, handling potentially null arrays in jq requires the `?` operator (e.g., `.sessions[]?`) when test tiers are run with mocked keys. Also, handling defaults like `(.sessions // [] | length)` is required to return a number instead of `null` and avoid breaking the array length. Additionally, you must use `IFS=$'\t' read -r` and `map(. // 0)` with `@tsv` to make sure empty values don't mess up bash reading variables positionally.
**Action:** When working in bash, never use multiple consecutive `jq` calls against the same data to extract scalar values. Always construct a single `jq` array payload extracting all needed values at once, safely parse defaults/nulls, pipe to `@tsv`, and assign them simultaneously via `IFS=$'\t' read -r ... <<< $(...)`.
