## 2024-06-25 - Batch jq Queries Performance Optimization
**Learning:** When evaluating shell script performance that calls `jq` repeatedly on the same JSON file or variable, creating new subshells and re-parsing the JSON in each call becomes a significant bottleneck. This codebase uses `.sessions[]` queries frequently to classify responses, causing repeated O(N) operations. Using `JULES_API_KEY=mock` resulted in mock API returning `{error: "Unauthorized"}` which lacks the `.sessions` array entirely, leading to iteration errors during test execution because of unhandled null outputs.
**Action:** When extracting multiple values from a single JSON payload using `jq`, always batch the queries into a single call. Use a `jq` array definition with `@tsv` and map the values to shell variables using `IFS=$'\t' read -r ... < <(...)`. To ensure robustness across all testing tiers (especially with mock keys), safely guard arrays and fields with the `?` operator (e.g., `.sessions[]?` or `.outputs[]?`) so `jq` degrades gracefully rather than throwing iteration errors when the expected keys do not exist in the JSON structure.
