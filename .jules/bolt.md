## 2024-03-24 - Batching jq Queries with @tsv
**Learning:** When writing bash test scripts that need to extract multiple fields from a single JSON payload using `jq`, sequential calls to `jq` introduce significant process spawning overhead (e.g., ~60ms overhead per test iteration). Batching these extractions into a single `jq` array construction and piping through `@tsv` to `IFS=$'\t' read -r` drastically improves performance (dropping it to ~10ms). However, if the parsed array contains missing values or null inputs, the optional operator `?` must be used with `.[]?` to avoid failing on nulls. Additionally, when using the optional `?` or default operators like `// empty` to construct the array, the length of the array passed to `@tsv` MUST be exactly the same length as the variables being read by `read -r`. Using `// empty` completely removes the element, so `// []` should be used for length counts to ensure a valid `0` is passed through `@tsv`.
**Action:** Always batch JSON extractions within bash performance scripts, but explicitly handle missing objects to preserve the array length for the `read` command.
