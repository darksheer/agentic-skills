## 2024-05-30 - Bash Test Suite Performance Optimization
**Learning:** In bash-based test suites that parse JSON, making repeated calls to `jq` on the same file/payload introduces significant subshell and binary startup overhead, leading to slower execution times (e.g. 10 individual `jq` process calls mapping separate metric queries). Also, when mapping to bash arrays or variables from a single `.tsv` output, empty spaces or `// empty` will strip out the array elements and break positional assignment.
**Action:** When working in bash test suites or shell scripts dealing with JSON evaluation, batch all related metric and extraction logic into a single `jq` invocation using a constructed array exported via `@tsv`, followed by extracting variables simultaneously with `IFS=$'\t' read -r var1 var2 ...`. Additionally use the `?` operator to safely iterate over potentially null properties, like `.sessions[]?`
