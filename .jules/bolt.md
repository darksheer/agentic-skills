## 2024-06-28 - Batched `jq` arrays vs sequential `jq` process spawning
**Learning:** In the bash-based test suite (`tests/run_all.sh`), executing multiple sequential `jq` commands against the same JSON payload is a performance bottleneck. The overhead comes from spawning separate `jq` processes and parsing the same JSON payload repeatedly. A secondary bottleneck was the parsing logic: when using `jq @tsv` with bash's `IFS=$'\t' read -r`, outputting empty strings (e.g. `// empty`) breaks positional assignment because bash collapses empty tab fields. Additionally, the mock API tests (`JULES_API_KEY=mock`) would return payloads without a `.sessions` array, causing `jq` failures.
**Action:** When working in bash test suites, batch `jq` operations into a single query using an array and `@tsv`. Read the output into bash variables simultaneously. Use the `?` operator (e.g., `.sessions[]?`) to gracefully handle `null` arrays from mock APIs, and use `// 0` or similar default values instead of `// empty` or empty strings to prevent bash from collapsing `tsv` delimiters during the `read -r` variable assignment.
