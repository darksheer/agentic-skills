## 2024-05-24 - Bash Script Performance Pattern (jq batching)
**Learning:** The bash test suite (`tests/run_all.sh`) repeatedly parsed the same large JSON output/files multiple times using separate `jq` processes. I learned from memory that batching these operations into a single `jq` array and parsing them using `IFS=$'\t' read -r ... < <(jq -r '... | @tsv')` avoids spawning multiple processes and reading the file multiple times. Also, consecutive whitespace delimiters collapse in Bash unless default assignments are handled properly (which was a constraint handled by not outputting empty strings inside `jq`), and we must handle `.sessions` that might be null using `?` for robustness, particularly during the pipeline dry-run where API failures happen.
**Action:** Consistently batch multi-field `jq` queries from the same JSON payload into a single `@tsv` array output to save I/O and process-spawning overhead in bash pipelines.
