## 2024-05-15 - Batched jq extractions and mock safety
**Learning:** Shell scripts repeatedly invoking `jq` against the same large JSON output introduces significant subprocess overhead (e.g., 10x slower for 10 extractions). Additionally, testing with mock endpoints (e.g., `JULES_API_KEY=mock`) returns JSON lacking expected arrays (like `.sessions`), which causes fatal `Cannot iterate over null` exceptions if queried directly.
**Action:** When extracting multiple values from a single JSON payload in bash, batch all queries into a single `jq` array and output with `@tsv`, reading it via `IFS=$'\t' read -r`. Always use the `?` operator (e.g., `.sessions[]?`) and handle potential `null` arrays (e.g., `(.field // [] | length)`) to ensure script robustness against mocked or empty API responses.
