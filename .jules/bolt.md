## 2024-07-23 - [Optimize Jules API Parsing]
**Learning:** The pipeline tests use repeated `jq` calls on the same `$sessions` JSON object causing massive overhead when processing the API response. In Bash, `jq` startup is slow and running it 10 times consecutively against a potentially large JSON string creates a measurable bottleneck in the CI/CD pipeline, and can fail completely when testing against a mock key due to `null` errors.
**Action:** Consolidate repeated `jq` queries into a single batched jq call outputting to `@tsv`, and use `IFS=$'\t' read -r ...` to assign to bash variables. Ensure fields inside `test()` are checked for nullness first and use the `?` operator for mapping arrays to correctly handle the mock environment. Ensure complex multilines aren't batched in this way.
