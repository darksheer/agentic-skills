## 2024-03-24 - Batching jq queries in bash performance tests
**Learning:** In bash test suites heavily relying on `jq`, repeatedly spawning `jq` processes for each piece of data is extremely slow (e.g., 0.059s vs 0.007s). Also, using `jq` on potentially null or missing arrays will fail (like when testing with mock APIs) unless the safe navigation `?` operator is used, e.g. `.sessions[]?` or `(.sessions // [])`. Finally, `test()` on `null` fails, so fields must be checked for existence first: `.title and (.title | test("..."))`.
**Action:** When extracting multiple values from the same JSON payload or file, batch the queries into a single `jq` call constructing an array and use `@tsv` with `IFS=$'\t' read -r ... <<< "$(jq -r ...)"`. Ensure safe navigation is used to prevent `null` iteration errors, and use `(.field // [] | length)` when counting lengths of potentially missing arrays.
