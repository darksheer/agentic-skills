## 2025-02-14 - Bash JSON Processing Bottleneck
**Learning:** Sequential `jq` calls in bash test suites create massive overhead. Processing a single JSON file four times with four subshells is significantly slower than batching queries into a single `jq` invocation using `@tsv` and parsing via `IFS=$'\t' read -r`. Additionally, using `?.` operators inside the `jq` queries is essential because mock APIs often omit arrays (e.g., returning only `{ "error": "unauthorized" }`), which causes `jq` iteration over null to fail.
**Action:** Always batch multiple JSON queries against the same document into a single `jq` array extraction. Use `IFS=$'\t' read -r var1 var2 <<< "$(jq -r '[...] | @tsv' ...)"` to load bash variables efficiently, and ensure mock data resilience with `?` (e.g. `.sessions[]?`).
